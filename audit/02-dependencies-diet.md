# Fase 2 — Dieta de dependencias

**Esfuerzo:** 2-4 h · **Riesgo:** Medio · **Breaking para el front:** No (si se verifica que el front no consume los endpoints de las apps eliminadas)

---

## 📌 Contexto

El `requirements.in` acumuló librerías "por las dudas" durante años. Varias nunca se usaron y arrastran dependencias pesadas (pandas + numpy ~100 MB instalados). Otras están marcadas como "#duda" por el propio autor. Esta fase las elimina y regenera el lockfile.

Antes de empezar leé [README.md](./README.md) para contexto general del proyecto.

---

## 🎯 Objetivo

- Eliminar 4 librerías directas del `requirements.in` que no se usan.
- Quitar de `INSTALLED_APPS` y `urls.py` las apps huérfanas que corresponden.
- Recompilar `requirements.txt` de forma determinista.
- Resolver la inconsistencia Python 3.12 vs 3.13.
- Ahorro esperado: **~150 MB en la imagen Docker** y varios segundos de import time.

---

### Paso 4 — Alinear Python (decidir 3.12 o 3.13)

**Recomendación: migrar a Python 3.13-slim.** Python 3.13 es estable desde octubre 2024, tiene mejoras de rendimiento y mejor tipado. Todas las libs en uso son compatibles.

**Archivo:** `Dockerfile:1`

**Estado actual:**
```dockerfile
FROM python:3.12.3
```

**Nuevo:**
```dockerfile
FROM python:3.13-slim
```

> Nota: `-slim` es más chica que la imagen default. **Atención**: `slim` no trae `gcc`, `libpq-dev`, `gettext`, etc. Hay que instalarlos explícitamente. Ver paso 5.

**Alternativa conservadora:** si querés mantener Python 3.12, dejar `python:3.12-slim` (no 3.12.3, para que los patches de seguridad lleguen automáticamente) y recompilar `requirements.txt` desde dentro del contenedor para que el header diga 3.12.

### Paso 5 — Ajustar Dockerfile para slim

**Estado actual (líneas completas):**
```dockerfile
FROM python:3.12.3

RUN apt update

ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1

WORKDIR /code

# We add this specific version of postgresql-client to avoid conflicts with the postgresql-client installed in the server
RUN apt-get install -y wget gnupg2 lsb-release && \
    echo "deb http://apt.postgresql.org/pub/repos/apt $(lsb_release -cs)-pgdg main" > /etc/apt/sources.list.d/pgdg.list && \
    wget --quiet -O - https://www.postgresql.org/media/keys/ACCC4CF8.asc | apt-key add -

RUN apt-get update && \
    apt-get install -y cron gettext vim postgresql-client-15 htop

RUN pip install --upgrade pip && \
    pip install pip-tools

COPY requirements.txt ./
RUN pip-sync requirements.txt

COPY . .

RUN chmod +x ./entrypoint.sh
RUN chmod +x ./entrypoint-dev.sh

# RUN mkdir -p /var/log/cron
```

**Nuevo (limpio, moderno, con `signed-by` en vez de `apt-key` deprecated, sin vim/htop/cron, postgres-client-16 para matchear el compose):**
```dockerfile
FROM python:3.13-slim

ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1
ENV PIP_NO_CACHE_DIR=1
ENV PIP_DISABLE_PIP_VERSION_CHECK=1

WORKDIR /code

# Instalar dependencias de sistema (slim no las trae)
# gettext: para makemessages/compilemessages
# postgresql-client-16: para pg_dump/pg_restore, matchea el servidor en compose
# gnupg/wget/ca-certificates: para agregar el repo oficial de Postgres
# libpq5: runtime de psycopg (binary ya lo trae, pero por si se cambia)
# build-essential: necesario si alguna wheel no está pre-buildeada
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        ca-certificates curl gnupg wget gettext libpq5 && \
    install -d /etc/apt/keyrings && \
    curl -fsSL https://www.postgresql.org/media/keys/ACCC4CF8.asc \
        | gpg --dearmor -o /etc/apt/keyrings/postgresql.gpg && \
    echo "deb [signed-by=/etc/apt/keyrings/postgresql.gpg] http://apt.postgresql.org/pub/repos/apt bookworm-pgdg main" \
        > /etc/apt/sources.list.d/pgdg.list && \
    apt-get update && \
    apt-get install -y --no-install-recommends postgresql-client-16 && \
    apt-get purge -y gnupg wget && \
    apt-get autoremove -y && \
    rm -rf /var/lib/apt/lists/*

RUN pip install --upgrade pip && pip install pip-tools

COPY requirements.txt ./
RUN pip-sync requirements.txt

COPY . .

RUN chmod +x ./entrypoint.sh ./entrypoint-dev.sh
```

> **Ojo con `bookworm-pgdg`**: es el codename de Debian 12 (lo que usa python:3.13-slim). Si cambiás la imagen base por otra Debian, ajustar (`trixie-pgdg` para Debian 13, etc.). Alternativa robusta: usar `$(. /etc/os-release && echo $VERSION_CODENAME)` dentro del RUN.
>
> **Nota Fase 4:** el paso 4 de la auditoría reemplaza `pip-tools` + `pip-sync` por `uv`. Si vas a hacer ambas fases seguidas, podés saltarte la instalación de pip-tools aquí y adoptar uv directamente.

### Paso 6 — Recompilar `requirements.txt`

**Es crítico hacerlo dentro del contenedor** para que el header del lockfile refleje la versión de Python real. Hay dos formas:

**Opción A — Con el Dockerfile ya editado del paso 5 (preferida):**

```bash
docker compose build web
docker compose run --rm web bash -c "pip install pip-tools && pip-compile --upgrade --output-file=requirements.txt requirements.in"
```

Esto:
1. Rebuild con el nuevo `requirements.in` ya editado.
2. Regenera `requirements.txt` con resolver corriendo dentro de Python 3.13.
3. El header del lockfile dirá "by Python 3.13".

**Opción B — Sin tocar Dockerfile todavía:**

```bash
docker run --rm -v "$PWD":/code -w /code python:3.13-slim bash -c "pip install pip-tools && pip-compile --upgrade --output-file=requirements.txt requirements.in"
```

Después del recompile, inspeccionar el diff:
```bash
git diff requirements.txt | head -80
```

Verificar que desaparecieron: `pandas`, `numpy`, `jsonfield`, `swapper`, `django-model-utils`, `pytz` (si no es transitiva de otra), `django-notifications-pro`, `django-global-places`, `requests-oauthlib`, `wheel`, `factory-boy`, `faker`.

## ⚠️ Riesgos y comunicación

| Riesgo | Mitigación |
|---|---|
| El front consume endpoints de `notifications` o `django_global_places` | **Pre-check obligatorio con el equipo de frontend antes de eliminar.** Si los usa, saltar esa lib. |
| Alguna lib transitiva que no sabíamos que necesitábamos se va | Revisar el diff del `requirements.txt`; correr tests y chequeo manual de endpoints. |
| Python 3.13 introduce incompatibilidad con alguna lib | Muy poco probable al 2026; si pasa, volver a 3.12-slim y recompilar. |
| `postgresql-client-16` no está en el repo default de Debian 12 (bookworm) | El Dockerfile agrega el repo oficial de Postgres; ya queda cubierto. |
